**Plugify** is a plugin manager written in C++. It is a library that an application loads to get plugins, and these plugins can be written in different programming languages and still call each other directly.

Plugify is not tied to one game. Today it is used most on **Counter-Strike 2** servers, where it comes as a ready-made [build](/builds), but any application can embed it.

## The idea

A plugin system usually supports one language. Plugify separates the two jobs:

- the **core** finds plugins, checks their dependencies, loads them in the right order and passes calls between them;
- a **language module** teaches the core one language: how to load a plugin in it and how to call its functions.

A plugin declares the functions it offers in its manifest. Any other plugin can call them, whatever language it is written in. A C# plugin can call a function of a C++ plugin and pass a callback written in Python to it, with no glue code on either side.

## What it consists of

| Part | What it does |
|---|---|
| **Core** | The library that manages everything: discovery, dependencies, load order, calls between languages |
| **Language modules** | One per language: C++, C#, Python, JavaScript, Go, Lua, Rust |
| **Plugins** | Your code. A plugin is a folder with a manifest (`*.pplugin`) and the files of its language |
| **Host** | The application that embeds the core. For Counter-Strike 2 these are S2-Launcher and MM-Loader |
| **Packages** | Modules and plugins are distributed as conda packages and installed with `mamba` |

## Where it is used

- **Game servers.** The [Plugify Source 2](/builds/source2) build turns a Counter-Strike 2 server into a platform for plugins in any supported language, with the Source 2 SDK plugin giving access to the game.
- **Your own application.** Embed the core to add plugins to an engine, a tool or a server, see [Core](/core).
