## Many languages, one system

Plugins can be written in any language that has a language module:

- **C++**: native plugins, called directly;
- **C# (.NET)**: plugins on .NET 10;
- **Python**: plugins on Python 3.12;
- **JavaScript**: plugins on the V8 engine;
- **Lua**: plugins on Lua 5.4;
- **Go**: native plugins built with cgo;
- **Rust**: native plugins.

Each module brings the runtime of its language, so nothing has to be installed on the machine where plugins run. A new language is added by writing a [language module](/core/language-modules/writing-language-module), without changing the core.

## Calls between languages

- **Exported methods.** A plugin lists the functions it offers in its manifest. Any other plugin can call them, whatever language either of them is written in.
- **Shared types.** Numbers, strings, arrays, vectors, matrices, values of any type and callbacks are passed between languages. A parameter can be passed by reference so that the called function can change it.
- **Callbacks.** A function written in one language can be passed to a plugin in another language and called from there.
- **Classes, enums and prototypes** described in the manifest give binding generators what they need to produce natural APIs for each language.
- **Native speed where possible.** Native plugins call each other through plain function pointers. Other languages go through small functions generated at run time.

## Dependencies and load order

- **Dependencies with version constraints**, such as `>=1.2.0 <2.0.0`, and optional dependencies.
- **Conflicts and replacements.** A plugin can declare plugins it cannot run with, and plugins it replaces.
- **Dependency resolution** with the [libsolv](https://github.com/openSUSE/libsolv) solver, the one used by Linux package managers.
- **Load order** computed from the dependencies. All plugins are loaded before the first one starts, so everything a plugin depends on is ready when it starts.
- **Clear failure reports.** If something does not start, the core says why, and the plugins that depend on it are skipped instead of crashing.

## Packages

Language modules and plugins are distributed as conda packages. The game server hosts include [micromamba](https://mamba.readthedocs.io/) and a console command to install, update and remove packages from channels.

## Embedding

- **A library with a small API.** A host creates the core, calls `Update` every frame and shuts it down. See [Integrating](/core/embedding/integrating).
- **Replaceable parts.** The logger, file system, library loader and dependency resolver can be replaced by your own implementations.
- **Platforms.** Windows, Linux and macOS on x86-64 and ARM64; the core also has platform code for Android, PlayStation and Nintendo Switch.

## Where it is used

- **Counter-Strike 2 servers**, through the ready-made [build](/builds) with the S2-Launcher or Metamod host and the [Source 2 SDK](/plugins/s2sdk/features) plugin.
- **Your own application**: an engine, a tool or a server that needs plugins in several languages.
