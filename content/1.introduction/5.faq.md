  #title
  What is Plugify?

  #content
  Plugify is a plugin manager written in C++. An application embeds it as a library and gets plugins that can be written in different languages and call each other directly. Today it is used most on Counter-Strike 2 servers, but any application can embed it. See [Overview](/introduction/overview).
  ::

  ::accordion-item
  #title
  Where to start?

  #content
  It depends on what you want to do:

  - **Run a server with plugins**: install the ready-made [build](/builds).
  - **Write plugins**: pick a language in [Plugins](/plugins).
  - **Embed Plugify or add a language**: start with [Core](/core). To try plugins without a game, build the `plug` test application, see [Installation](/core/embedding/installation).
  ::

  ::accordion-item
  #title
  How many languages are supported?

  #content
  Seven languages have a language module: **C++**, **C# (.NET)**, **Python**, **JavaScript** (V8), **Lua**, **Go** and **Rust**. See [Languages](/plugins/languages).

  Support for another language is added with a new [language module](/core/language-modules/writing-language-module); the core does not change.
  ::

  ::accordion-item
  #title
  Where can I find plugins?

  #content
  The base plugins (Source 2 SDK, configs, permissions and others) are in [Plugins](/plugins) and in the `plugify-plugin-*` repositories of the [untrustedmodders](https://github.com/untrustedmodders) organization. Community plugins are shared on the [Discord server](https://discord.gg/rX9TMmpang).
  ::

  ::accordion-item
  #title
  How do plugins in different languages talk to each other?

  #content
  A plugin lists the methods it exports in its manifest. Every method becomes a native function with the C calling convention of the platform, and every language module makes the methods of all plugins callable in its language. Strings, arrays, vectors and other complex values are passed in the common `plg::` types of the core, and callbacks can be passed in both directions. See [Architecture](/core/architecture#calls-between-languages).
  ::

  ::accordion-item
  #title
  What platforms does Plugify support?

  #content
  The core builds and runs on **Windows**, **Linux** and **macOS**, on **x86-64** and **ARM64**. It also has platform code for Android, PlayStation and Nintendo Switch. The Counter-Strike 2 build is for Windows and Linux, 64-bit.
  ::

  ::accordion-item
  #title
  How do I create a new language module?

  #content
  1. Start from the [plugify-module-template](https://github.com/untrustedmodders/plugify-module-template) repository.
  2. Implement the `ILanguageModule` interface and export the `GetLanguageModule()` function.
  3. Set your language in the `.pmodule` manifest.
  4. Put the module into the `extensions` folder of `plug` together with a plugin in your language and check that both reach `Running`.

  See [Writing Language Module](/core/language-modules/writing-language-module).
  ::

  ::accordion-item
  #title
  How do I install and update plugins and modules?

  #content
  Modules and plugins are conda packages. The core itself has no package manager: it loads what it finds in its extensions folder. The Counter-Strike 2 hosts include **micromamba** and a `mamba` console command that installs, updates and removes packages from channels. See [Commands](/builds/management/commands).
  ::

  ::accordion-item
  #title
  What are manifest files?

  #content
  Manifests are JSON files (comments allowed) that describe an extension. Keys that are not in the schema make a manifest invalid.

  1. **`*.pplugin`** describes a plugin: its language, entry point, dependencies and exported methods. `name` uses letters, digits and `_`.
     ```json [my_plugin.pplugin]
     {
       "$schema": "https://raw.githubusercontent.com/untrustedmodders/plugify/refs/heads/main/schemas/plugin.schema.json",
       "name": "my_plugin",
       "version": "1.0.0",
       "description": "An example plugin",
       "author": "Your Name",
       "website": "https://example.com",
       "license": "MIT",
       "language": "cpp",
       "entry": "bin/my_plugin",
       "dependencies": []
     }
     ```

  2. **`*.pmodule`** describes a language module: the language it serves.
     ```json [cpp_module.pmodule]
     {
       "$schema": "https://raw.githubusercontent.com/untrustedmodders/plugify/refs/heads/main/schemas/module.schema.json",
       "name": "cpp_module",
       "version": "1.0.0",
       "description": "Adds support for C++ plugins",
       "author": "Your Name",
       "website": "https://example.com",
       "license": "MIT",
       "language": "cpp"
     }
     ```

  3. **`*.pconfig`** holds settings of the core: folders, loading, security and logging. It is optional and read only when the host passes it to the core. The Counter-Strike 2 hosts set their folders themselves and do not use it.
     ```json [plugify.pconfig]
     {
       "$schema": "https://raw.githubusercontent.com/untrustedmodders/plugify/refs/heads/main/schemas/config.schema.json",
       "paths": {
         "baseDir": ".",
         "extensionsDir": "extensions"
       },
       "logging": {
         "severity": "debug",
         "printReport": true
       }
     }
     ```

  All fields are described in [Architecture](/core/architecture#extensions-and-manifests).
  ::

  ::accordion-item
  #title
  How should the files be laid out?

  #content
  The core looks for manifests in its extensions folder and its subfolders. A folder that contains a manifest is not searched further, and one folder may hold several manifests. A language module keeps its library in `bin/` next to its manifest:

     ::file-tree
     ---
     tree:
     - ^extensions^:
        - cpp_module:
           - bin:
              - cpp_module.dll
              - libcpp_module.so
           - cpp_module.pmodule
        - my_plugin:
           - bin:
              - my_plugin.dll
              - libmy_plugin.so
           - my_plugin.pplugin
        - my_script:
           - my_script.py
           - my_script.pplugin
     ---
     ::

  On a Counter-Strike 2 server the extensions folder is `csgo/addons/plugify/envs`, see [Directory Structure](/builds/management/directory-structure).
  ::

  #title
  How do I debug plugins and language modules?

  #content
  1. Read the report the core logs after loading: it says why each extension did not start.
  2. Raise the log level: `logging.severity` set to `debug` in a `.pconfig` for your own host or `plug`, or `--verbosity=<level>` on the command line of S2-Launcher.
  3. Build the part you debug with symbols and run the application under a debugger.

  See [Debugging](/core/contributing/debugging).

  #title
  What do I need to build the core?

  #content
  - A compiler with C++23 support: GCC, Clang, MSVC (Visual Studio 2022) or Apple Clang. C++20 is the lowest supported standard.
  - CMake 3.14 or later.
  - A 64-bit platform: x86-64 or ARM64.

  The libraries the core needs are downloaded by CMake. See [Requirements](/introduction/requirements) and [Build Instructions](/core/embedding/building).
  ::

  ::accordion-item
  #title
  How do I remove Plugify?

  #content
  - **From a game server**: remove the host (S2-Launcher or the Metamod plugin) as described on its installation page, and delete the `csgo/addons/plugify` folder with the installed modules and plugins.
  - **From your application**: remove the core library from your project and delete the folder with extensions, if you no longer need it.
