A **build** is a ready-to-run Plugify pack for a game: the host that loads Plugify into the game, the language modules and the base plugins, tested together and released as one archive. You extract it into the game folder and start the server, with nothing else to install.

## Build or packages one by one?

Both give the same result on disk: the build puts its packages into the usual `envs/modules` and `envs/plugins` environments, and `mamba` works with them as with packages you installed yourself. The build's set is marked by a meta-package, so `mamba list` shows which build version is installed.

| | Build | Packages one by one |
|---|---|---|
| What you download | One archive | The host, then each module and plugin with `mamba install` |
| Versions | A set tested together, one version number for the whole pack | The latest version of each package |
| Updating | `mamba update` moves the whole set to the next build; your own packages and configs are kept | `mamba update` per package, to the latest version of each |
| Good for | Setting up a server, reproducing a setup, support | Picking individual packages, trying new versions early |

You can mix the two: install a build and then add any other package with `mamba install`.

## Versions and channels

- **stable**: releases with their own version (`1.0.0`), tagged `plugify-source2-v1.0.0`. Every release lists the exact version of every component.
- **dev**: rebuilt on every change to the build, with versions like `1.0.1-dev.12`. For testing new component versions before they reach stable.
