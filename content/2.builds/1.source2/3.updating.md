A build is updated in two parts:

- **Packages** (language modules and plugins) are updated with `mamba` from the server console. No archive is needed.
- **The host** is updated with the host-only archive, and only when a new build changes it. The [Changelog](/builds/source2/changelog) marks such releases.

Your settings in `configs/`, `data/` and `logs/`, the packages you added yourself and your other environments in `envs/` are kept.

## Updating packages

In the server console:

```bash
plg unload
mamba update -n modules --all
mamba update -n plugins --all
plg load
```

The build's set is a meta-package: `plugify-source2-modules` in `envs/modules` and `plugify-source2-plugins` in `envs/plugins`. Its version is the build version, and it depends on the exact versions of the build's packages. So `mamba update` moves the standard packages to the next build's versions, installs packages the new build added and removes the ones it dropped. Packages you installed yourself are updated from their own channels.

To see which build is installed:

```bash
mamba list -n plugins
```

The `plugify-source2-plugins` line shows the build version. Every other package that this meta-package doesn't depend on was added by you.

## Updating the host

Needed only when the [Changelog](/builds/source2/changelog) says the host changed. Update the packages first, then:

::steps
### Stop the server

### Save `sentry.jsonc`
With the Launcher and Runtime hosts, copy `game/bin/<platform>/sentry.jsonc` if you changed it. The archive replaces it.

### Extract the host-only archive
Download `plugify-source2-<host>-<os>-<version>-host-only` for your host and OS on the [download page](/builds/source2) and extract it into the server's root folder, replacing files. It has no `envs/`, so your packages stay as they are.

### Start the server
Put your `sentry.jsonc` back if you saved it, and start the server.
::

::alert{icon="lucide:info"}
Don't extract the full archive over an installed build: the package records in `conda-meta/` would keep the old versions next to the new ones. The full archive is for a new installation, or after you delete `envs/modules` and `envs/plugins`.
::

## Other operations

Install a specific build version, for example to roll back:

```bash
plg unload
mamba install -n plugins plugify-source2-plugins=0.9.0
mamba install -n modules plugify-source2-modules=0.9.0
plg load
```

Keep a package newer than the build has it: first detach the environment from the build. The packages stay installed, and from then on you manage their versions yourself:

```bash
plg unload
mamba remove -n plugins --no-prune-deps plugify-source2-plugins
mamba update -n plugins plugify-plugin-s2sdk
plg load
```

Removing one of the build's plugins (`mamba remove -n plugins plugify-plugin-dyncall`) also removes the meta-package, so the environment stops following builds. Installing `plugify-source2-plugins` again brings it back.
