The **Configs** plugin (`configs`) reads configuration files for other plugins. A plugin in any language calls it to load its settings, read values by key and merge several files into one, so the defaults that ship with a package and the edits of a server owner end up in a single config.

## What it does

- **Reads JSON and JSONC.** JSONC is JSON with comments, the format the base plugins use for their settings.
- **Merges layers.** `ReadMultiple` reads a list of files in order, and each next file overrides the keys of the previous ones. Missing files are skipped.
- **Typed access.** `GetBool`, `GetInt`, `GetFloat` and `GetString` return a value or the default you pass. The `GetAs*` variants convert between types.
- **Navigation.** `JumpKey`, `JumpFirst`, `JumpNext` and `JumpBack` walk through objects and arrays, like a cursor.
- **Building configs.** `Make`, `Set*` and `Push*` create a config in memory, and `RootToJsonString` turns it into JSON text.
- **One API for every language.** The functions are exported through the plugin manifest, and a `Config` class wraps the handle in languages that support classes.

## When to use it

- Your plugin has settings a server owner should be able to change.
- You ship defaults in the package and want user edits to survive updates.
- You need the same config format as the base plugins, see [Configuration](/builds/management/configuration).
