This guide shows how a plugin calls a native function by its address with the **DynCall** plugin. The examples are in Python. The functions are the same in every language, see [Import Functions](/plugins/languages) for how your language calls them.

## Add the dependency

Declare `dyncall` in the manifest of your plugin, so it is loaded before yours:

```json
"dependencies": [
  { "name": "dyncall" }
]
```

## Call a function

Say the address `func` points to this function:

```c++
double add(double a, double b);
```

Create a call VM, push the arguments in order and call the function with the `Call*` variant of its return type:

```python
from plugify.pps import dyncall as dc

vm = dc.NewVM(4096)          # 4096 bytes for the arguments
dc.Reset(vm)                 # clear the arguments of the previous call
dc.ArgDouble(vm, 2.0)
dc.ArgDouble(vm, 3.5)
result = dc.CallDouble(vm, func)   # 5.5
dc.Free(vm)
```

A VM can be used for many calls: call `Reset` before each one. Free it with `Free` when you no longer need it. `GetError(vm)` returns a non-zero code if the last call failed.

## Types

| C type | Push | Call |
|---|---|---|
| `bool` | `ArgBool` | `CallBool` |
| `char` | `ArgChar` | `CallChar` |
| `int8_t` … `uint64_t` | `ArgInt8`, `ArgUInt8`, `ArgInt16`, `ArgUInt16`, `ArgInt32`, `ArgUInt32`, `ArgInt64`, `ArgUInt64` | `CallInt8` … `CallUInt64` |
| `float` | `ArgFloat` | `CallFloat` |
| `double` | `ArgDouble` | `CallDouble` |
| `void*` | `ArgPointer` | `CallPointer` |
| `const char*` | `ArgString` | `CallString` |
| no value | | `CallVoid` |

`ArgString` copies the string and keeps the copy until the VM is freed. `CallString` copies the returned C string into a string of your language.

For a C++ method pass `this` as the first argument with `ArgPointer`.

## Calling conventions

A new VM uses the default convention of the platform. `Mode(vm, mode)` changes it, `mode` is a number from `dyncall.h`:

| Mode | Value |
|---|---|
| Platform default | `0` |
| C++ method, platform default (`this` is the first argument) | `99` |
| Variadic function, fixed arguments | `100` |
| Variadic function, the `...` part | `101` |
| Windows x64 | `7` |
| System V x64 (Linux) | `8` |

`GetModeFromCCSigChar` returns the mode for a calling convention character of a dyncall signature, for example `:` for the default.

## Example: a function from gamedata

The address usually comes from a signature in [gamedata](/plugins/s2sdk/guides/gamedata). Here `GetCSWeaponDataFromKey(int, const char*)` from the gamedata of the Source 2 SDK returns the data of a weapon:

```python
from plugify.pps import s2sdk as s2
from plugify.pps import dyncall as dc

func = s2.GetGameConfigSignatureAll("GetCSWeaponDataFromKey")

vm = dc.NewVM(4096)
dc.Reset(vm)
dc.ArgInt32(vm, -1)
dc.ArgString(vm, "weapon_ak47")
weapon_data = dc.CallPointer(vm, func)
dc.Free(vm)
```

## Structures by value

A function that takes or returns a structure by value needs its layout:

1. `NewAggr(fieldCount, size)` creates a description of a structure of `size` bytes.
2. `AggrField(aggr, type, offset, arrayLength)` adds a field. `type` is a `SigChar`, for example `SigChar.Int` or `SigChar.Float`.
3. `CloseAggr(aggr)` finishes the description.
4. `ArgAggr(vm, aggr, value)` pushes a structure from the memory at `value`. For a returned structure call `BeginCallAggr(vm, aggr)` before pushing the arguments, then `CallAggr(vm, func, aggr, returnValue)` writes the result to `returnValue`.
5. `FreeAggr(aggr)` frees the description.

## Notes

- The arguments must match the signature of the function exactly, in count, order and types. A wrong type is undefined behaviour.
- The address must point to a function with the same signature on every platform. Game functions often differ between Windows and Linux.

The full list of functions with their signatures is on the [API Hub](https://api.plugify.net/?file=https://raw.githubusercontent.com/untrustedmodders/plugify-plugin-dyncall/refs/heads/main/plugify-plugin-dyncall.pplugin.in).
