Ideas for Plugify are welcome. This page explains how to suggest one so that it can be discussed and considered.

## How to suggest a feature

::steps
### Check existing requests
Look through the [open feature requests](https://github.com/untrustedmodders/plugify/issues?q=is%3Aissue+is%3Aopen+label%3Aenhancement) and [discussions](https://github.com/untrustedmodders/plugify/discussions). If your idea is already there, add a 👍 reaction and your use case in a comment.

### Pick the right repository
A request for the core goes to [plugify](https://github.com/untrustedmodders/plugify/issues). A request for a language module, a host or a plugin goes to the issues of that repository.

### Open an issue
Click **New issue** and describe the feature. If you are not sure the idea fits, start a discussion or ask on [Discord](https://discord.gg/rX9TMmpang) first.
::

## What to include

```markdown
### Description
What the feature does.

### Use case
What problem it solves and who needs it.

### Alternatives
How you work around it today.

### Additional context
Examples, links to similar features elsewhere, sketches.
```

## Tips

- **Describe the problem, not only the solution.** The use case helps find the best way to solve it.
- **One feature per request.**
- **Be specific**: which part of Plugify, which language, which host.

## What happens next

The developers read the request and discuss it in the issue. Accepted ideas are marked and implemented when there is time; pull requests that implement them are welcome, see [How to Contribute](/core/contributing/how-to-contribute).
