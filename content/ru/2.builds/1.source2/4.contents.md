В билд входят языковые модули тех языков, на которых написаны его плагины. Когда в билде появится плагин на другом языке, например на JavaScript, вместе с ним появится и модуль его языка.

## Раскладка на диске

Архив распаковывается в папку `game/` сервера. Пример для загрузчика Launcher на Linux:

::file-tree
---
tree:
- game:
    - bin:
        - linuxsteamrt64:
            - ^s2launcher^
            - libplugify.so
            - libsentry.so
            - crashpad_handler
            - sentry.jsonc
    - csgo:
        - addons:
            - plugify:
                - bin:
                    - linuxsteamrt64:
                        - micromamba
                - envs:
                    - modules:
                        - bin/
                        - plugify-module-cpp.pmodule
                        - plugify-module-golang.pmodule
                        - conda-meta/
                    - plugins:
                        - bin/
                        - plugify-plugin-s2sdk.pplugin
                        - s2sdk.gamedata.jsonc
                        - s2sdk.settings.jsonc
                        - s2sdk.translations.jsonc
                        - conda-meta/
                - configs/
                - data:
                    - s2sdk:
                        - s2sdk.translations.jsonc
                    - permissions:
                        - permissions_connector_s2.translations.yaml
                - logs/
                - pkgs/
                - ^.condarc^
                - build.json
---
::

Отличия загрузчиков:

- **Runtime**: вместо `s2launcher` загрузчиком служит `csgo/bin/linuxsteamrt64/libserver_valve.so`.
- **Metamod**: в `bin/` ничего не кладётся; `csgo/addons/metamod/plugify.vdf` загружает `csgo/addons/plugify/bin/<platform>/libplugify`.

Переводы стандартных плагинов в `data/` приходят только с полным архивом: `mamba` их не обновляет, а в архиве загрузчика их нет.

### Мета-пакеты

Набор билда записан средствами самой conda. `plugify-source2-plugins` (в `envs/plugins`) и `plugify-source2-modules` (в `envs/modules`) являются пакетами без файлов, которые зависят от точных версий пакетов билда. Их версия совпадает с версией билда. `mamba list` показывает, какой билд установлен, а `mamba update` переводит набор на следующий билд, см. [Обновление](/ru/builds/source2/updating).

### .condarc и build.json

В `addons/plugify/.condarc` первым указан conda-канал билда, за ним каналы компонентов и всех языковых модулей. Поэтому эти пакеты ставятся по имени, без `-c`. Пакетам из других каналов нужен `-c`.

В `addons/plugify/build.json` записано, с каким билдом пришёл загрузчик, а также версии загрузчика и ядра.

## Добавление пакетов

`envs/modules` и `envs/plugins` являются обычными conda-окружениями. Операции с пакетами выполняются, пока Plugify выгружен:

```bash
plg unload
mamba install -n modules plugify-module-python3
mamba install -n plugins -c "https://example.github.io/my-plugin/" my-plugin
plg load
```

Если пакет есть в билде, ставится его версия из билда. Остальные пакеты берутся из своих каналов: из перечисленных в `.condarc` или из переданного через `-c`.

Свои плагины можно держать и в отдельном окружении, потому что Plugify находит пакеты во всех папках `envs/`:

```bash
plg unload
mamba create -n my-plugins
mamba install -n my-plugins <package>
plg load
```

Плагины без пакета кладутся в отдельную папку в `envs/`, например `envs/my_plugin/`.

Добавленные так пакеты сохраняются при [обновлении](/ru/builds/source2/updating) билда. Если вы пишете плагины на языке, модуль которого билд может позже убрать, установите этот модуль явно (`mamba install -n modules plugify-module-golang`), и он останется.
