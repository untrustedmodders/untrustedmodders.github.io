title: Check Transmit
description: Как контролировать видимость объектов и передачу по сети с помощью системы CheckTransmit.
---

Система CheckTransmit в Source 2 позволяет контролировать, какие объекты передаются по сети конкретным игрокам. Эта мощная функция позволяет создавать продвинутые игровые механики, такие как скрытие/показ объектов, создание правил видимости для конкретных игроков и оптимизация сетевого трафика.

::callout{icon="i-lucide-eye" color="blue"}
**Что такое CheckTransmit?**: CheckTransmit вызывается каждый тик для определения, какие объекты должны быть переданы (по сети) каждому игроку. Подключившись к этой системе, вы можете динамически контролировать, что видит каждый игрок.
::

## Обзор

Для работы с системой CheckTransmit необходимо:

1. **Зарегистрировать хук** с помощью `OnServerCheckTransmit_Register` при запуске плагина
2. **Получать указатели CheckTransmitInfo** для каждого клиента в вашем колбэке
3. **Изменять состояния передачи** используя предоставленные методы
4. **Отменить регистрацию хука** с помощью `OnServerCheckTransmit_Unregister` (с тем же колбэком) при завершении плагина

::callout{icon="i-lucide-info" color="amber"}
**Предупреждение о производительности**: CheckTransmit вызывается **каждый тик** для каждого клиента. Делайте логику вашего колбэка эффективной, чтобы избежать проблем с производительностью сервера.
::

Чтобы просто скрыть объект от одного игрока, встроенные `HideTransmitEntity(playerSlot, entityHandle)` и `ShowTransmitEntity(playerSlot, entityHandle)` делают это без колбэка.

## Структура CheckTransmitInfo

Каждый объект `CCheckTransmitInfo` содержит информацию о состояниях передачи для одного клиента. В списке есть игроки и SourceTV (боты не получают сетевых данных). **Слот игрока хранится в структуре** (`m_nPlayerSlot`), а не задаётся индексом массива.

- **m_pTransmitEntity**: BitVec, контролирующий, какие объекты передаются
- **m_pNonTransmitEntity**: BitVec объектов, которые существуют на клиенте, но не передаются (методы `NonPlayer`)
- **m_pTransmitOutOfPVS**: BitVec объектов, которые вышли из PVS, но ещё требуют дельта-обновления
- **m_pTransmitAlways**: BitVec объектов, которые передаются всегда, даже вне PVS (SourceTV и replay)
- **m_LoadedSpawnGroups**: Список spawn group, загруженных клиентом
- **m_nPlayerSlot**: Слот игрока этого клиента
- **m_bFullUpdate**: Должно ли быть отправлено полное обновление

::callout{icon="i-lucide-info" color="blue"}
**Слот игрока**: Читайте его через `GetTransmitInfoPlayerSlot(info)` (или `info.GetPlayerSlot()`). `infos[0]` не обязательно относится к слоту 0.
::

::callout{icon="i-lucide-layers" color="green"}
**Объяснение BitVec**: BitVec - это эффективная структура данных, которая использует отдельные биты для отслеживания состояний объектов. Каждая позиция бита соответствует индексу объекта.
::

## Доступные методы

S2SDK предоставляет два способа работы с CheckTransmitInfo:

### 1. Функциональный API (прямые вызовы методов)

Используйте эти методы, передавая указатель CheckTransmitInfo в качестве первого параметра:

#### Методы передачи объектов
```csharp
SetTransmitInfoEntity(info, entityHandle);          // Mark entity as transmittable
ClearTransmitInfoEntity(info, entityHandle);        // Mark entity as not transmittable
IsTransmitInfoEntitySet(info, entityHandle);        // Check if entity is transmittable
SetTransmitInfoEntityAll(info);                     // Mark all entities as transmittable
ClearTransmitInfoEntityAll(info);                   // Mark all entities as not transmittable
```

#### Методы списка непередаваемых объектов
```csharp
SetTransmitInfoNonPlayer(info, entityHandle);       // Mark entity as existing but not transmitted
ClearTransmitInfoNonPlayer(info, entityHandle);     // Remove entity from the non-transmit list
IsTransmitInfoNonPlayerSet(info, entityHandle);     // Check if entity is in the non-transmit list
SetTransmitInfoNonPlayerAll(info);                  // Mark all entities as non-transmitted
ClearTransmitInfoNonPlayerAll(info);                // Clear the non-transmit list
```

#### Методы объектов вне PVS
```csharp
SetTransmitInfoOutOfPVS(info, entityHandle);        // Mark entity as out of PVS but still updated
ClearTransmitInfoOutOfPVS(info, entityHandle);      // Unmark entity
IsTransmitInfoOutOfPVSSet(info, entityHandle);      // Check if entity is marked
SetTransmitInfoOutOfPVSAll(info);                   // Mark all entities
ClearTransmitInfoOutOfPVSAll(info);                 // Unmark all entities
```

#### Методы постоянной передачи
```csharp
SetTransmitInfoAlways(info, entityHandle);          // Mark entity to always transmit
ClearTransmitInfoAlways(info, entityHandle);        // Unmark entity from always transmit
IsTransmitInfoAlwaysSet(info, entityHandle);        // Check if entity always transmits
SetTransmitInfoAlwaysAll(info);                     // Mark all entities to always transmit
ClearTransmitInfoAlwaysAll(info);                   // Unmark all entities from always transmit
```

#### Методы целевых spawn group
```csharp
GetTransmitInfoTargetSpawnGroupsCount(info);        // Get count of loaded spawn groups
GetTransmitInfoTargetSpawnGroup(info, index);       // Get spawn group by index
AddTransmitInfoTargetSpawnGroup(info, spawnGroup);  // Add a spawn group
RemoveTransmitInfoTargetSpawnGroup(info, index);    // Remove spawn group by index
GetTransmitInfoTargetSpawnGroupsAll(info);          // Get all spawn groups
RemoveTransmitInfoTargetSpawnGroupsAll(info);       // Clear all spawn groups
```

#### Методы слота игрока и полного обновления
```csharp
GetTransmitInfoPlayerSlot(info);                    // Get the client's player slot
SetTransmitInfoPlayerSlot(info, playerSlot);        // Set the client's player slot
GetTransmitInfoFullUpdate(info);                    // Get full update flag
SetTransmitInfoFullUpdate(info, fullUpdate);        // Set full update flag
```

## Практические примеры

### Пример 1: Скрыть конкретный объект от всех игроков

::tabs{variant="card"}
  ::div{label="c#" icon="vscode-icons:file-type-csharp2"}
  ```csharp
  using Plugify;
  using s2sdk;
  using static s2sdk.s2sdk;

  public unsafe class HideEntity : Plugin
  {
      private int hiddenEntityHandle = -1;

      public void OnPluginStart()
      {
          OnServerCheckTransmit_Register(OnCheckTransmit);

          // Add console command to hide an entity
          AddConsoleCommand("hide_entity", "Hide an entity by index",
              ConVarFlag.LinkedConcommand | ConVarFlag.Release,
              Command_HideEntity, HookMode.Post);
      }

      public void OnPluginEnd()
      {
          OnServerCheckTransmit_Unregister(OnCheckTransmit);
      }

      private ResultType Command_HideEntity(int caller, ConCommandContext context, string[] arguments)
      {
          if (arguments.Length < 2)
          {
              PrintToServer("Usage: hide_entity <entity_index>\n");
              return ResultType.Handled;
          }

          int entityIndex = int.Parse(arguments[1]);
          hiddenEntityHandle = EntIndexToEntHandle(entityIndex);

          if (IsValidEntHandle(hiddenEntityHandle))
          {
              PrintToServer($"Entity {entityIndex} will be hidden from all players\n");
          }
          else
          {
              PrintToServer($"Invalid entity index: {entityIndex}\n");
          }

          return ResultType.Handled;
      }

      private void OnCheckTransmit(nint[] infos)
      {
          if (hiddenEntityHandle == -1 || !IsValidEntHandle(hiddenEntityHandle))
              return;

          // Hide entity from all players
          foreach (nint info in infos)
          {
              ClearTransmitInfoEntity(info, hiddenEntityHandle);
              // Keep it on the client as "exists but not transmitted"
              SetTransmitInfoNonPlayer(info, hiddenEntityHandle);
          }
      }
  }
  ```

### Пример 2: Создание видимости для конкретных игроков

Скрывайте объекты от конкретных игроков на основе условий:

::tabs{variant="card"}
  ::div{label="c#" icon="vscode-icons:file-type-csharp2"}
  ```csharp
  using Plugify;
  using s2sdk;
  using static s2sdk.s2sdk;
  using System.Collections.Generic;

  public unsafe class PlayerVisibility : Plugin
  {
      // Map of player slot -> list of hidden entity handles
      private Dictionary<int, List<int>> playerHiddenEntities = new();

      public void OnPluginStart()
      {
          OnServerCheckTransmit_Register(OnCheckTransmit);
      }

      public void OnPluginEnd()
      {
          OnServerCheckTransmit_Unregister(OnCheckTransmit);
      }

      // Hide a specific entity from a specific player
      public void HideEntityFromPlayer(int playerSlot, int entityHandle)
      {
          if (!playerHiddenEntities.ContainsKey(playerSlot))
          {
              playerHiddenEntities[playerSlot] = new List<int>();
          }

          if (!playerHiddenEntities[playerSlot].Contains(entityHandle))
          {
              playerHiddenEntities[playerSlot].Add(entityHandle);
          }
      }

      // Show a previously hidden entity to a player
      public void ShowEntityToPlayer(int playerSlot, int entityHandle)
      {
          if (playerHiddenEntities.ContainsKey(playerSlot))
          {
              playerHiddenEntities[playerSlot].Remove(entityHandle);
          }
      }

      private void OnCheckTransmit(nint[] infos)
      {
          foreach (nint ptr in infos)
          {
              // Using OOP style
              var info = new CheckTransmitInfo(ptr);
              int playerSlot = info.GetPlayerSlot();

              // Check if this player has any hidden entities
              if (playerHiddenEntities.ContainsKey(playerSlot))
              {
                  foreach (int entityHandle in playerHiddenEntities[playerSlot])
                  {
                      // Only hide if entity is still valid
                      if (IsValidEntHandle(entityHandle))
                      {
                          info.ClearEntity(entityHandle);
                          info.SetNonPlayer(entityHandle);
                      }
                  }
              }
          }
      }
  }
  ```

### Пример 3: Скрыть игроков друг от друга

Создать "режим невидимости", где конкретные игроки не видят друг друга:

::tabs{variant="card"}
  ::div{label="c#" icon="vscode-icons:file-type-csharp2"}
  ```csharp
  using Plugify;
  using s2sdk;
  using static s2sdk.s2sdk;
  using System.Collections.Generic;

  public unsafe class InvisibleMode : Plugin
  {
      private HashSet<int> invisiblePlayers = new();

      public void OnPluginStart()
      {
          OnServerCheckTransmit_Register(OnCheckTransmit);

          AddConsoleCommand("toggle_invisible", "Toggle invisible mode",
              ConVarFlag.LinkedConcommand | ConVarFlag.Release | ConVarFlag.ClientCanExecute,
              Command_ToggleInvisible, HookMode.Post);
      }

      public void OnPluginEnd()
      {
          OnServerCheckTransmit_Unregister(OnCheckTransmit);
      }

      private ResultType Command_ToggleInvisible(int caller, ConCommandContext context, string[] arguments)
      {
          if (caller == -1) return ResultType.Handled;

          if (invisiblePlayers.Contains(caller))
          {
              invisiblePlayers.Remove(caller);
              PrintToChat(caller, "Invisible mode: OFF");
          }
          else
          {
              invisiblePlayers.Add(caller);
              PrintToChat(caller, "Invisible mode: ON");
          }

          return ResultType.Handled;
      }

      private void OnCheckTransmit(nint[] infos)
      {
          foreach (nint ptr in infos)
          {
              var info = new CheckTransmitInfo(ptr);
              int receiverSlot = info.GetPlayerSlot();

              // For each invisible player
              foreach (int invisibleSlot in invisiblePlayers)
              {
                  // Don't hide from themselves
                  if (invisibleSlot == receiverSlot)
                      continue;

                  // Get invisible player's pawn handle (the controller is not the visible model)
                  int controllerHandle = PlayerSlotToEntHandle(invisibleSlot);
                  int invisibleHandle = GetEntSchemaEnt(controllerHandle, "CCSPlayerController", "m_hPlayerPawn", 0);

                  if (IsValidEntHandle(invisibleHandle))
                  {
                      // Hide invisible player from this receiver
                      info.ClearEntity(invisibleHandle);
                      info.SetNonPlayer(invisibleHandle);
                  }
              }
          }
      }
  }
  ```

### Пример 4: Показывать только членов команды

Отображать объекты только игрокам из той же команды:

::tabs{variant="card"}
  ::div{label="c#" icon="vscode-icons:file-type-csharp2"}
  ```csharp
  using Plugify;
  using s2sdk;
  using static s2sdk.s2sdk;
  using System.Collections.Generic;

  public unsafe class TeamVisibility : Plugin
  {
      // Map of entity handles to teams
      private Dictionary<int, CSTeam> teamEntities = new();

      public void OnPluginStart()
      {
          OnServerCheckTransmit_Register(OnCheckTransmit);
      }

      public void OnPluginEnd()
      {
          OnServerCheckTransmit_Unregister(OnCheckTransmit);
      }

      // Register an entity to be visible only to a specific team
      public void SetEntityTeamVisibility(int entityHandle, CSTeam team)
      {
          teamEntities[entityHandle] = team;
      }

      private void OnCheckTransmit(nint[] infos)
      {
          foreach (nint ptr in infos)
          {
              var info = new CheckTransmitInfo(ptr);
              int playerSlot = info.GetPlayerSlot();

              // Get player's team
              CSTeam playerTeam = GetClientTeam(playerSlot);

              // Check each team-restricted entity
              foreach (var kvp in teamEntities)
              {
                  int entityHandle = kvp.Key;
                  CSTeam requiredTeam = kvp.Value;

                  if (!IsValidEntHandle(entityHandle))
                      continue;

                  // Hide entity if player is not on the correct team
                  if (playerTeam != requiredTeam)
                  {
                      info.ClearEntity(entityHandle);
                      info.SetNonPlayer(entityHandle);
                  }
                  else
                  {
                      // Ensure it's visible to team members
                      info.SetEntity(entityHandle);
                  }
              }
          }
      }
  }
  ```

### Пример 5: Контроль полного обновления

Принудительно отправлять полные обновления для конкретных ситуаций:

::tabs{variant="card"}
  ::div{label="c#" icon="vscode-icons:file-type-csharp2"}
  ```csharp
  using Plugify;
  using s2sdk;
  using static s2sdk.s2sdk;
  using System.Collections.Generic;

  public unsafe class FullUpdateControl : Plugin
  {
      private HashSet<int> playersNeedingFullUpdate = new();

      public void OnPluginStart()
      {
          OnServerCheckTransmit_Register(OnCheckTransmit);

          // Hook player spawn to force full update
          HookEvent("player_spawn", Event_PlayerSpawn, HookMode.Post);
      }

      public void OnPluginEnd()
      {
          OnServerCheckTransmit_Unregister(OnCheckTransmit);
      }

      private ResultType Event_PlayerSpawn(string name, nint @event, Bool8 dontBroadcast)
      {
          int playerSlot = GetEventPlayerSlot(@event, "userid");

          // Mark player for full update on next transmit
          playersNeedingFullUpdate.Add(playerSlot);
          return ResultType.Continue;
      }

      private void OnCheckTransmit(nint[] infos)
      {
          foreach (nint ptr in infos)
          {
              var info = new CheckTransmitInfo(ptr);
              int playerSlot = info.GetPlayerSlot();

              // Check if this player needs a full update
              if (playersNeedingFullUpdate.Contains(playerSlot))
              {
                  info.SetFullUpdate(true);

                  // Remove after applying once
                  playersNeedingFullUpdate.Remove(playerSlot);

                  PrintToServer($"Sending full update to player {playerSlot}\n");
              }
          }
      }
  }
  ```

## Справочник методов

### Операции с Entity BitVec

| Метод | Описание |
|--------|-------------|
| `SetEntity(entityHandle)` | Отметить объект как передаваемый этому игроку |
| `ClearEntity(entityHandle)` | Отметить объект как не передаваемый этому игроку |
| `IsEntitySet(entityHandle)` | Проверить, отмечен ли объект для передачи |
| `SetEntityAll()` | Отметить все объекты как передаваемые |
| `ClearEntityAll()` | Отметить все объекты как не передаваемые |

### Операции со списком непередаваемых объектов

| Метод | Описание |
|--------|-------------|
| `SetNonPlayer(entityHandle)` | Отметить объект как существующий на клиенте, но не передаваемый |
| `ClearNonPlayer(entityHandle)` | Убрать объект из списка непередаваемых |
| `IsNonPlayerSet(entityHandle)` | Проверить, есть ли объект в списке непередаваемых |
| `SetNonPlayerAll()` | Отметить все объекты как непередаваемые |
| `ClearNonPlayerAll()` | Очистить список непередаваемых |

### Операции с объектами вне PVS

| Метод | Описание |
|--------|-------------|
| `SetOutOfPVS(entityHandle)` | Отметить объект как вне PVS, но обновляемый |
| `ClearOutOfPVS(entityHandle)` | Снять отметку с объекта |
| `IsOutOfPVSSet(entityHandle)` | Проверить, отмечен ли объект |
| `SetOutOfPVSAll()` | Отметить все объекты |
| `ClearOutOfPVSAll()` | Снять отметку со всех объектов |

### Операции постоянной передачи

| Метод | Описание |
|--------|-------------|
| `SetAlways(entityHandle)` | Принудительно всегда передавать объект (SourceTV и replay) |
| `ClearAlways(entityHandle)` | Снять флаг принудительной передачи |
| `IsAlwaysSet(entityHandle)` | Проверить, принудительно ли передается объект |
| `SetAlwaysAll()` | Принудительно всегда передавать все объекты |
| `ClearAlwaysAll()` | Очистить все флаги принудительной передачи |

### Операции с целевыми spawn group

| Метод | Описание |
|--------|-------------|
| `GetTargetSpawnGroupsCount()` | Получить количество загруженных spawn group |

| `RemoveTargetSpawnGroup(index)` | Удалить spawn group по индексу |

## Лучшие практики

::callout{icon="i-lucide-check-circle" color="green"}
**Советы по производительности**:
- Кэшируйте хэндлы объектов вне колбэка CheckTransmit, когда это возможно
- Проверяйте хэндлы перед их использованием в CheckTransmit
- Избегайте дорогих операций в колбэке (вызывается каждый тик!)
- Используйте ранние возвраты, чтобы пропустить ненужную обработку
::

1. ✅ **Всегда регистрируйте во время OnPluginStart** и отменяйте регистрацию во время OnPluginEnd
2. ✅ **Проверяйте хэндлы объектов** перед использованием их в операциях передачи
3. ✅ **Делайте логику колбэка минимальной** - CheckTransmit выполняется каждый тик
4. ✅ **Используйте ООП обёртку** для более чистого и читаемого кода (когда доступно)
5. ✅ **Кэшируйте часто используемые данные** вне колбэка
6. ❌ **Не выполняйте тяжёлые вычисления** в колбэке CheckTransmit
7. ❌ **Не забывайте отменять регистрацию** - могут возникнуть утечки памяти и сбои
8. ❌ **Не предполагайте, что объекты валидны** - всегда проверяйте хэндлы

## Устранение неполадок

### Объекты всё ещё видны после очистки
**Проблема**: `ClearEntity()` вызван, но объект всё ещё виден
**Решение**: Применяйте изменение каждый тик (движок пересобирает битовые наборы каждый тик) и очищайте нужный объект: для игрока это pawn, а не контроллер

### Проблемы с производительностью
**Проблема**: Задержки сервера после реализации CheckTransmit
**Решение**: Профилируйте ваш колбэк - вероятно, выполняется слишком много работы за тик. Кэшируйте данные и минимизируйте операции.

### Изменения не применяются
**Проблема**: Модификации передачи, похоже, не работают
**Решение**: Убедитесь, что вы изменяете правильный CheckTransmitInfo для целевого игрока. Проверьте, что хэндлы объектов валидны.

### Хук не работает
**Проблема**: Колбэк никогда не вызывается
**Решение**: Проверьте, что вы зарегистрировали хук во время `OnPluginStart` и что плагин S2SDK загружен.

## Заключение

Система CheckTransmit - это мощный инструмент для контроля видимости объектов в Source 2. Подключившись к решениям сервера о передаче, вы можете создавать сложные игровые механики, оптимизировать сетевой трафик и создавать уникальный игровой опыт.

Ключевые моменты:
- Регистрируйте хуки в `OnPluginStart`, отменяйте регистрацию в `OnPluginEnd`
- Используйте функциональный или ООП API в зависимости от предпочтений
- Делайте колбэки эффективными - они выполняются каждый тик
- Всегда проверяйте хэндлы объектов перед использованием
- При скрытии объекта очищайте бит Entity и устанавливайте бит NonPlayer
