Плагин **Configs** (`configs`) читает файлы конфигурации для других плагинов. Плагин на любом языке вызывает его, чтобы загрузить свои настройки, прочитать значения по ключу и слить несколько файлов в один. Так значения по умолчанию из пакета и правки владельца сервера оказываются в одном конфиге.

## Что он делает

- **Читает JSON, JSONC, YAML и TOML.** Формат выбирается по расширению файла: `.json`, `.jsonc`, `.yaml` или `.yml`, `.toml` или `.tml`. JSONC это JSON с комментариями, в этом формате базовые плагины хранят свои настройки.
- **Сливает слои.** `ReadMultiple` читает список файлов по порядку, и каждый следующий файл перекрывает ключи предыдущих. Отсутствующие файлы пропускаются.
- **Типизированный доступ.** `GetBool`, `GetInt`, `GetFloat` и `GetString` возвращают значение или переданное вами значение по умолчанию. Варианты `GetAs*` преобразуют типы.
- **Навигация.** `JumpKey`, `JumpFirst`, `JumpNext` и `JumpBack` перемещаются по объектам и массивам, как курсор.
- **Создание конфигов.** `Make`, `Set*` и `Push*` собирают конфиг в памяти, а `RootToJsonString` превращает его в текст JSON.
- **Один API для всех языков.** Функции экспортируются через манифест плагина, а в языках с поддержкой классов хэндл оборачивает класс `Config`.

## Когда использовать

- У вашего плагина есть настройки, которые владелец сервера должен иметь возможность менять.
- Вы поставляете значения по умолчанию в пакете и хотите, чтобы правки пользователя переживали обновления.
- Вам нужен тот же формат конфигов, что у базовых плагинов, см. [Конфигурация](/ru/builds/management/configuration).
