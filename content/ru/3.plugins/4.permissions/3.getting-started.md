Эта страница ведёт от только что установленного сервера к рабочему набору групп, по одной команде за раз. Если вы уже знаете LuckPerms или PermissionsEx, начните с раздела [Для тех, кто знает LuckPerms или PermissionsEx](#для-тех-кто-знает-luckperms-или-permissionsex). Полный список команд и настроек есть в [Руководстве](/ru/plugins/permissions/guide).

## Основные понятия

### Право

Плагины защищают свои команды и возможности **правами**. Право это строка из слов, разделённых точками, например `admin.kick`. Строку выбирает плагин, а вы решаете, у кого она есть.

Для игрока у права три возможных ответа:

- **разрешено**: строка есть у игрока или у одной из его групп;
- **запрещено**: строка выдана с `-` в начале, например `-admin.kick`;
- **не задано**: право нигде не упомянуто. Плагины считают это тем же, что и запрет.

`*` в конце это wildcard: `admin.*` покрывает все права, которые начинаются с `admin.`, а одиночная `*` покрывает всё.

### Группа

Выдавать права каждому игроку по одному неудобно. **Группа** это именованный набор прав, который выдаётся игроку целиком: положите `admin.kick` и `admin.ban` в группу `Moderator`, а затем добавляйте игроков в `Moderator`.

Игрок может состоять в нескольких группах сразу и вдобавок иметь личные права.

### Наследование

У группы может быть **родитель**, и она получает все его права. Если у `Admin` родитель `Moderator`, а у `Moderator` родитель `Default`, то у администратора есть права всех трёх групп.

У группы один родитель. Чтобы совместить несвязанные наборы прав, добавьте игрока в несколько групп.

### Приоритет

У каждой группы есть **приоритет**, число, которое вы задаёте при создании. Когда две группы игрока расходятся в ответе на одно право, побеждает группа с большим приоритетом. Обычно группе по умолчанию дают `0`, а более высоким рангам числа побольше.

### Группа по умолчанию

В новой базе есть одна группа, `Default`, с приоритетом `0`. Её получает каждый игрок при входе. Права, которые вы положите в `Default`, действуют на всех.

## Перед началом

- Должны быть установлены все три плагина. Они входят в билд [Plugify Source 2](/ru/builds/source2), а как поставить их отдельно, описано на странице [Установка](/ru/plugins/permissions/installation).
- Команды с этой страницы вводите в **консоль сервера**. Консоли разрешено всё, поэтому первый администратор создаётся именно там.
- Изменить можно только игрока, который **находится на сервере**. Игроки загружаются при входе и выгружаются при выходе.
- `<player>` в команде это имя, `#слот`, `$steamid64` или `&account_id`. Команда `perms_users` показывает игроков на сервере с их слотами и SteamID64.

## Шаг 1: Выдайте доступ себе

Зайдите на сервер, затем выполните в консоли сервера команду со своим SteamID64:

```bash
perms_user_add_permission $76561198000000000 permissions.* 0
```

Теперь у вас есть все права, которые начинаются с `permissions.`, то есть все команды `perms_*`. Последний аргумент это срок, и `0` означает навсегда.

Дальше команды можно вводить и в игре, в консоли или в чате. Команда `perms` покажет доступные вам команды.

## Шаг 2: Создайте группу

```bash
perms_creategroup Admin 100 "" "admin.* permissions.*"
```

Аргументы: имя группы, её приоритет, родитель и права.

- `Admin` это имя.
- `100` это приоритет.
- `""` означает, что родителя нет.
- `"admin.* permissions.*"` это список прав, в кавычках и через пробел. Чтобы создать пустую группу, передайте `""`.

Добавлять и убирать права группы позже можно так:

```bash
perms_group_add_permission Admin shop.*
perms_group_remove_permission Admin shop.*
```

`perms_group_permissions Admin` показывает, что есть у группы сейчас, а `perms_groups` выводит список всех групп.

## Шаг 3: Добавьте игрока в группу

```bash
perms_user_add_group $76561198000000000 Admin 0
```

Теперь у игрока есть все права группы `Admin`. Забрать группу обратно:

```bash
perms_user_remove_group $76561198000000000 Admin
```

`perms_user_groups <player>` показывает группы игрока.

## Шаг 4: Постройте лестницу групп

Допустим, серверу нужны четыре ранга. Строки прав здесь условные, свои вы возьмёте из плагинов, которыми пользуетесь.

| Default | VIP | Moderator | Admin |
|---|---|---|---|
| `shop.buy` | `shop.discount` | `admin.kick` | `admin.*` |
| | `chat.color` | `admin.mute` | `permissions.*` |

У каждого ранга должны быть и права рангов ниже. Для этого и нужен родитель:

```bash
perms_group_add_permission Default shop.buy
perms_creategroup VIP 10 Default "shop.discount chat.color"
perms_creategroup Moderator 50 VIP "admin.kick admin.mute"
perms_group_parent_set Admin Moderator
```

`Default` уже существует, поэтому ей только добавляется право. `VIP` и `Moderator` создаются сразу с родителем. `Admin` существует с шага 2, поэтому родитель ему задаётся отдельной командой.

Наследование идёт до самого верха: у модератора есть права `Moderator`, `VIP` и `Default`. Цепочку родителей, которая замыкается на ту же группу, система не примет.

## Шаг 5: Заберите одно право

Wildcard выдаёт всё, что под ним. Чтобы оставить wildcard и убрать одно право, добавьте **запрет**, ту же строку с `-` в начале:

```bash
perms_group_add_permission Admin -admin.ban
```

Теперь у администраторов есть всё под `admin.`, кроме `admin.ban`. То же работает для одного игрока:

```bash
perms_user_add_permission <player> -chat.color 0
```

Если у группы или игрока эта строка уже есть с противоположным ответом, `add` откажется её менять. Используйте `perms_group_set_permission` или `perms_user_set_permission`, они заменяют текущий ответ.

## Шаг 6: Выдайте временный доступ

Группы и права игрока могут истекать сами. Передайте срок вместо `0`:

```bash
perms_user_add_group <player> VIP 2592000
```

По умолчанию срок задаётся в секундах, так что это 30 дней. Чтобы вводить срок в минутах, часах или днях, измените `time_mode` в [настройках коннектора](/ru/plugins/permissions/guide#настройки-коннектора).

Когда время выйдет, группа снимется, а игрок получит об этом сообщение. `perms_user_set_group` заменяет срок группы, которая у игрока уже есть.

## Шаг 7: Проверьте результат

Не гадайте, работает ли настройка, спросите у системы:

```bash
perms_user_check_permission <player> admin.kick
perms_user_info <player>
perms_group_check_permission Moderator admin.kick
```

`perms_user_info` выводит об игроке всё: группы, личные права, cookie и иммунитет.

## Когда правила расходятся

Игрок может получить разные ответы на одно право из разных мест. Побеждает первое место, где есть ответ:

1. временные права игрока;
2. постоянные права игрока;
3. группы игрока, от большего приоритета к меньшему. Сначала отвечает сама группа, затем её родитель, затем родитель родителя.

Внутри одного игрока или одной группы точная строка сильнее wildcard: `admin.*` вместе с `-admin.ban` запрещает `admin.ban` и разрешает остальное.

| Настройка | Проверка | Ответ | Почему |
|---|---|---|---|
| Игрок: `-shop.buy`. Группа `Default`: `shop.buy` | `shop.buy` | запрещено | Личные права игрока идут раньше групп |
| `Admin` (100): `admin.*`. `Muted` (5): `-admin.kick`. Игрок в обеих | `admin.kick` | разрешено | У `Admin` приоритет выше, и ответ у неё уже есть |
| `Admin` (100): `admin.*`. `Muted` (200): `-admin.kick`. Игрок в обеих | `admin.kick` | запрещено | Теперь первой спрашивают `Muted` |
| `VIP`: `-shop.discount`, родитель `Default`: `shop.*` | `shop.discount` | запрещено | Группа отвечает раньше своего родителя |

Вторая строка удивляет чаще всего: запрет в младшей группе не перекрывает старшую. Дайте ограничивающей группе больший приоритет или выдайте запрет самому игроку.

### Иммунитет

Иммунитет определяет, на кого администратор может действовать. Администратор может действовать на игрока, только когда его иммунитет равен или выше. У нового игрока иммунитет `0`. Иммунитет задают плагины через API, консольной команды для него нет.

## Опции групп

Кроме прав, у группы могут быть **опции**: именованные значения, которые читают плагины, например тег в чате или лимит.

```bash
perms_group_set_option VIP tag "[VIP]"
perms_group_option VIP tag
```

Сама по себе опция ничего не делает. Имя и смысл значения описывает плагин, который её использует. У игроков могут быть и личные значения, они называются cookie, и cookie игрока перекрывает одноимённую опцию из групп.

## Несколько серверов

С MySQL или PostgreSQL несколько серверов могут работать с одной базой. У каждого сервера свой `server_id` в [настройках хранилища](/ru/plugins/permissions/guide#хранилище):

- группы и права, выданные на сервере `0`, действуют на всех серверах;
- выданные на другом id действуют только там;
- снятие группы или права с игрока снимает их на всех серверах. Чтобы забрать право только на одном сервере, добавьте на нём запрет.

SQLite это всегда один сервер.

## Где искать строки прав

- Читайте документацию плагина. Обычно плагины начинают свои строки со своего имени.
- Права команд `perms_*` перечислены в [таблице команд](/ru/plugins/permissions/guide#команды).
- Доверенной группе администраторов выдайте wildcard на весь плагин, например `shop.*`, и добавьте запреты на то немногое, что ей делать нельзя.

## Частые проблемы

**Игрок не найден.** Игрок должен быть на сервере. Проверьте написание или используйте `#слот` либо `$steamid64` из `perms_users`.

**Команда из чата отвечает, что у вас нет прав.** Каждой команде `perms_*` нужно своё право. Выдайте себе `permissions.*` из консоли сервера, как в шаге 1.

**Вам не разрешено действовать на игрока.** У цели иммунитет выше вашего.

**Право выдано, а игрок всё равно не может пользоваться возможностью.** Выполните `perms_user_check_permission`. Если ответ «запрещено», ищите запрет у игрока или в группе с большим приоритетом, см. [Когда правила расходятся](#когда-правила-расходятся). Если ответ «разрешено», плагин проверяет другую строку.

**Группа не удаляется.** В ней ещё есть игроки, или это группа по умолчанию.

**На MySQL или PostgreSQL после перезапуска ничего не сохранилось.** В этих базах плагин не создаёт таблицы. Создайте их, как описано в разделе [Хранилище](/ru/plugins/permissions/guide#хранилище).

**Нет вывода через RCON.** Ответ команды `perms_*` печатается в консоль сервера и клиенту RCON не возвращается.

## Для тех, кто знает LuckPerms или PermissionsEx

Система прав построена на тех же идеях, что и эти два плагина. Таблица сопоставляет знакомое с тем, что есть здесь.

| LuckPerms | PermissionsEx | Plugify Permissions |
|---|---|---|
| `lp user <u> permission set <p> true` | `pex user <u> add <p>` | `perms_user_add_permission <u> <p> 0` |
| `lp user <u> permission set <p> false` | `pex user <u> add -<p>` | `perms_user_add_permission <u> -<p> 0` |
| `lp user <u> permission unset <p>` | `pex user <u> remove <p>` | `perms_user_remove_permission <u> <p>` |
| `lp user <u> parent add <g>` | `pex user <u> group add <g>` | `perms_user_add_group <u> <g> 0` |
| `lp user <u> parent addtemp <g> 30d` | `pex user <u> group add <g> "" 2592000` | `perms_user_add_group <u> <g> 2592000` |
| `lp creategroup <g>` | `pex group <g> create` | `perms_creategroup <g> <priority> "" ""` |
| `lp group <g> parent add <parent>` | `pex group <g> parents set <parent>` | `perms_group_parent_set <g> <parent>` |
| `lp group <g> setweight <n>` | `pex group <g> weight <n>` | Приоритет, задаётся в `perms_creategroup` |
| `lp group <g> meta set <key> <value>` | `pex group <g> set <option> <value>` | `perms_group_set_option <g> <key> <value>` |
| `lp user <u> info` | `pex user <u>` | `perms_user_info <u>` |
| `lp user <u> permission check <p>` | `pex user <u> check <p>` | `perms_user_check_permission <u> <p>` |

В чём отличия:

- **Запреты** пишутся как в PermissionsEx, с `-` перед строкой. Аргумента `true` или `false` нет.
- **Вес** называется приоритетом и обязателен для каждой группы.
- У группы **один родитель**. Игрок при этом может состоять в нескольких группах.
- **Контексты** ограничены сервером: `server_id` в настройках хранилища.
- **Игроки загружены только пока они на сервере**, поэтому игрока вне сервера командой изменить нельзя.
- Треков и лестниц рангов с командами повышения и понижения нет. Переведите игрока, сняв одну группу и добавив другую.
- Веб-редактора и файла прав для ручной правки нет. Всё делается командами или через [API](/ru/plugins/permissions/guide#авторам-плагинов).
